# Стиль Mini App — Студия ботов

Единый технический и визуальный фундамент для всех проектов Студии ботов
(Мойка, Прокат-Инструмента, ВЕРСТА, барбершоп-варианты, order-bot, most-cafe
и новые). Каждый новый проект = новый файл (или набор файлов по ролям) поверх
этого фундамента, с собственной акцентной палитрой и текстами под нишу.

## Не путать со studio-site-style

Этот skill — только про Mini App внутри Telegram (не индексируется
поисковиками, SEO не нужен в принципе). Для многостраничных сайтов студии
(Astro/Netlify, tg-studio.by и клиентские лендинги) — отдельный skill
studio-site-style, где дизайн и SEO идут вместе. Токены
палитры/шрифтов общие — studio-site-style берёт их отсюда.


## Стек проекта (контекст, не переопределять без просьбы)

Ванильные HTML/CSS/JS без сборки → ветка `gh-pages` → GitHub Pages
(`birsiti.github.io/TG-Studio/…`) → открывается как Telegram Mini App из
бота в LEADTEX (no-code). **Имена и пути HTML-файлов не менять** — на них
ведут кнопки Web App в LEADTEX.

- Общий код — папка `kit/` в корне репо: `kit/core.js` (глобальный `Kit`)
  и `kit/base.css` (компоненты на CSS-переменных). Каждый бот — своя
  папка со своим `brand.css` (палитра, шрифты, форма углов, фирменные
  элементы) и `mock.js` (двойник серверного контракта в браузере).
- Бэкенд — `api/` (Python 3.12, FastAPI + SQLite, отдельная база на бота),
  работает на iMac за `https://api.tg-studio.xyz`. Протокол: `POST
  /api/<бот>`, тело `{"action": "...", ...payload}`, `Content-Type:
  text/plain`, ответ `{ok, ...}`. Подробно — `api/README.md`.
- Google Apps Script / Sheets (`Code.gs`) — архив, новых action туда не
  добавлять.

Каркас страницы роли:


`kit/core.js` сам делает `tg.ready()`, `expand()`, `disableVerticalSwipes()`,
ставит тему до первой отрисовки, красит шапку/низ Telegram под `--bg`,
прокидывает `safeAreaInset`/`contentSafeAreaInset` в CSS-переменные и
управляет нативной `BackButton` для шторок. Свой boilerplate не писать.

Первая строка каждого изменённого файла — комментарий
`изменено ГГГГ-ММ-ДД ЧЧ:ММ` (`<!-- -->` в HTML, `/* */` в CSS, `//` в JS,
`#` в Python).

## Чек-лист перед сдачей любого HTML-файла

1. Подключены `telegram-web-app.js`, `kit/core.js`, `kit/base.css`,
   `brand.css`, `mock.js` (в этом порядке)?
2. В `viewport` есть `viewport-fit=cover`?
3. В шапке есть `<button data-theme-toggle>` (солнышко → панель темы)?
4. Все запросы идут через `Kit.createApi` — без API страница работает на
   моке, без ошибок в консоли?
5. Проверено на ширине 375px в светлой И тёмной теме, по основному
   сценарию роли?
6. Нет `:hover`, все кнопки ≥44px, шрифт ≥16px у полей ввода и основного
   текста, никаких эмодзи в интерфейсе — только SVG (`Kit.icon`)?

## Тема: Авто / Тёмная / Светлая

Telegram открывает Mini App в теме пользователя — оба варианта обязаны
работать. В шапке каждой роли — иконка-солнышко; по тапу открывается
панель «Авто / Тёмная / Светлая», после выбора панель **закрывается сама**.
Всё это делает `kit/core.js`, достаточно разметки:

```html
<button class="icon-btn" type="button" data-theme-toggle aria-label="Оформление"></button>
```

- Иконка подставляется автоматически (солнце/луна/авто по текущему режиму).
- Выбор хранится в `localStorage['tgs-theme']` (`auto` | `dark` | `light`),
  общий для всех ботов на домене.
- «Авто» = `tg.colorScheme` в Telegram, иначе `prefers-color-scheme`;
  реагирует на `themeChanged`.
- На `<html>` ставится `data-theme="light|dark"` синхронно, до отрисовки —
  вспышки чужой темы нет.
- Программно: `Kit.theme.set('dark')`, `Kit.theme.choice()` (выбор пользователя), `Kit.theme.resolved()` (итоговая тема).

Палитра — **одна фирменная на бота**, в `brand.css`, в двух блоках:

```css
:root{ --font-display:'…'; --font-body:'…'; --font-mono:'…'; --r-lg:18px; --btn-radius:14px; }
:root[data-theme="light"]{ --bg:…; --surface:…; --surface-2:…; --surface-3:…; --ink:…; --ink-2:…; --ink-3:…;
  --line:…; --line-2:…; --accent:…; --accent-2:…; --accent-ink:…; --accent-soft:…;
  --ok:…; --ok-soft:…; --warn:…; --warn-soft:…; --danger:…; --danger-soft:…; --shadow-1:…; --shadow-2:…; }
:root[data-theme="dark"]{ …те же имена… }
```

Имена переменных не менять — на них построены все компоненты `kit/base.css`.
**Переключатели скинов/палитр не делать** — у бота одно лицо.

## Telegram WebApp: правила

- Без hover-эффектов (только `:active`), зоны нажатия ≥44px (`--tap`).
- Safe-area: `viewport-fit=cover` + отступы через `max()` — в `kit/base.css`
  уже есть `--safe-top/--safe-bottom/--gutter-l/--gutter-r`.
- Шрифт ≥16px у полей ввода (иначе iOS зумит) и основного текста.
- Слова не переносить по слогам/дефису: `Kit.nobr(text)` для названий с
  дефисом; если не влезает — уменьшать шрифт (`data-fit="min"` на
  элементе — `Kit.fit` подберёт размер), а не ломать слово.
- Иконки — только SVG: `Kit.icon('calendar')` (набор в `kit/core.js`),
  нишевые наборы — в файле бота (`tools.js`, `dishes.js`).
- Подтверждения — `await Kit.confirm(msg, okLabel, danger)` (внутри Telegram
  это `showConfirm`), уведомления — `Kit.toast(msg, 'ok'|'error')`,
  виброотклик — `Kit.haptic('light'|'select'|'success'|'error'|'warning')`.
- Шторки — `Kit.sheet({title, sub, body, actions, onClose})` → `{el, body, $, close}`;
  нативная `BackButton` закрывает верхнюю шторку автоматически.
- Обработчики событий вешать один раз (делегирование `Kit.on(root, 'click',
  '[data-x]', fn)` при инициализации), а не внутри функций перерисовки —
  иначе клики начинают срабатывать по два раза.

## API и демо-режим

```js
const api = Kit.createApi({bot:'barbershop', mock: window.BarberMock});
const r = await api('getSlots', {date:'2026-10-09'});  // userId добавляется сам
if(!r.ok){ Kit.toast(r.message || 'Не получилось', 'error'); return; }
```

- URL: `https://api.tg-studio.xyz/api/<бот>`; для локальной проверки —
  `?api=http://localhost:8097` (только на localhost).
- Если API недоступен (сеть, 5xx, таймаут 6 с) — **тихий откат на мок**
  до конца сессии; демо не ломается. Если связь была и пропала — `{ok:false,
  error:'network'}`, подмены данных нет.
- `userId` = `tg.initDataUnsafe.user.id`, вне Telegram — постоянный `web-…`
  из `localStorage` (`Kit.user`).
- `mock.js` повторяет контракт сервера и хранит состояние в `localStorage`,
  общем для всех ролей бота: запись клиента видна в админке того же браузера.
- Цены, скидки, доставку считает сервер; клиент только показывает.

## Телефон — маска +375, всегда

```js
$('#box').innerHTML = String(Kit.phone.field('phone', savedE164)); // +375 и поле XX-XXX-XX-XX
const el = $('#phone'); Kit.phone.bind(el);
Kit.phone.valid(el);      // 9 цифр после +375
Kit.phone.value(el);      // '+375291234567' — в payload
Kit.phone.pretty(e164);   // '+375 29 123-45-67' — для показа
```

Префикс не редактируется, сервер проверяет формат `+375XXXXXXXXX`.

## Известные баги Telegram WebApp — уже закрыты в kit

1. `env(safe-area-inset-*)` = 0 на части устройств → `kit/core.js` берёт
   `tg.safeAreaInset`/`contentSafeAreaInset`, CSS — `max()` с минимумом.
2. Шторка «подглядывает» снизу → `.sheet` скрывается
   `transform + opacity + visibility` вместе.
3. Mini App открывается на пол-экрана → не подключён
   `telegram-web-app.js` в `<head>`: проверять первым делом.
4. Дата/время: браузер может жить в другом часовом поясе — даты считать
   через `Kit.date` (`today`, `add`, `label`, `when`), сервер работает в
   Europe/Minsk.

## Структура ролей (для многоролевых проектов)

Каждая роль — отдельный HTML-файл (отдельная кнопка Web App в LEADTEX):

- `client.html` — сценарий клиента (выбор → подтверждение → «тикет»)
- `admin.html` — операционная панель (сегодня / список / поиск+фильтр)
- `owner.html` — аналитика (выручка, топы, загрузка, CSV-экспорт)
- `driver.html`, `mechanic.html` — если в домене есть исполнитель

Все роли бота ходят в один `api/<бот>` и один `mock.js`.

## Подключение готового файла к боту в LEADTEX

Файл сам по себе — просто HTML на GitHub Pages, ссылка на него ничего не
открывает внутри Telegram, пока её не подключили в боте правильным типом
кнопки (обычная URL-кнопка откроет системный браузер, а не Mini App).

В сценарии бота (LEADTEX, `app.leadteh.ru`) в блоке **«Кнопки»** у каждой
кнопки, которая должна открывать Mini App:

1. Открыть настройку кнопки (шестерёнка на кнопке в редакторе сценария).
2. **Тип кнопки → Web App** (не «Ссылка» — та откроет обычный браузер).
3. **URL** — прямая ссылка на опубликованный файл, например
   `https://birsiti.github.io/<repo>/client.html`.
4. Сохранить.

Портфолио-бот студии (`@TG_Studio_BY` / `t.me/tg_studio_BY_bot`) устроен
как меню кнопок такого типа, по одной на кейс (Блеск, Верста, Барбершоп,
Аренда инструмента, Бот-визитка) плюс «Заказать бота» — тот же паттерн
масштабируется на любое число демо-кейсов, просто новая кнопка Web App на
новый файл.

## Ролевое ветвление сценария по тегу

Кроме «своя роль = свой Web App-файл» (см. «Структура ролей» выше), в самом
сценарии LEADTEX роль можно разделить ещё до Mini App — блоком **«Условие»**
(Да/Нет) сразу после «Старт», который проверяет **тег пользователя**
(теги назначаются администратором боту вручную/по правилу). Если у
пользователя есть тег владельца — сценарий ведёт в ветку с
дополнительными кнопками (аналитика, служебные функции), которых нет у
обычного клиента. Это не альтернатива ролевым HTML-файлам, а
дополнительный уровень: тег решает, **какие кнопки вообще видны** в
сценарии бота, а отдельный `role.html` — что открывается **внутри**
Mini App после нажатия. Комбинировать оба уровня — нормальный паттерн для
проектов с владельцем/админом, которым нужны скрытые от клиента функции.

## Типовая структура сценария в LEADTEX

Разбор реального сценария портфолио-бота — шаблон для новых кейсов, не
изобретать заново под каждый проект:

```
Старт
  └─ Условие (Да/Нет — тег пользователя, см. «Ролевое ветвление по тегу»)
       └─ Приветствие (Цепочка сообщений)
            кнопки: [аналитика/статистика] · Меню
            └─ «Меню» → Главное меню (Цепочка сообщений)
                 кнопки: [Кейс 1] · [Кейс 2] · ... · Заказать бота · Любая другая фраза
                 └─ [Кейс N] → Блок кейса (Цепочка сообщений)
                      кнопки: Меню клиента · Меню администратора · Меню владельца · [Меню водителя — если в домене есть исполнитель на выезде]
                      В меню · Любая другая фраза
                      └─ [Меню роли] → Кнопка Web App → конкретный `role.html` на GitHub Pages
```

Правила, которые видны из этой структуры и стоит повторять в новых
сценариях:

- **Каждый уровень меню — это один блок «Цепочка сообщений»**, не отдельные
  сообщения вразнобой — так весь уровень редактируется в одном месте.
- **«В меню» есть в каждом блоке кейса** — без него пользователь, зайдя в
  конкретный кейс, не может вернуться наверх иначе как перезапуском бота.
- **«Любая другая фраза» есть на каждом уровне** — перехватывает
  нестандартный ввод (опечатка, произвольный текст), чтобы бот не терялся
  молча.
- Роль (клиент/администратор/владелец/водитель) — это отдельная кнопка
  Web App на отдельный HTML-файл (`client.html`, `admin.html`, `owner.html`,
  `driver.html` — см. «Структура ролей» выше), а не разные экраны внутри
  одного файла с переключателем.


## Чего не делать

- Не подключать сборщики/фреймворки — ванильные HTML/CSS/JS + `kit/`.
- Не хранить токены и ключи в клиентском коде — секреты только в
  переменных окружения `api/` (см. `api/README.md`).
- Не дублировать в файле бота то, что уже есть в `kit/` (тема, шторки,
  тосты, маска телефона, даты) — править `kit/`, если чего-то не хватает.
- Не делать переключатели палитр/скинов и hover-эффекты.
- Не звать `window.confirm`/`window.alert` напрямую — только `Kit.confirm`
  / `Kit.toast`.
- Не переименовывать и не переносить HTML-файлы ролей — сломаются кнопки
  в LEADTEX.
