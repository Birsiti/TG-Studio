# taxi-morning-digest

Отдельный бот (не часть основной "Будни"), который:

1. Читает чат такси-диспетчерской [t.me/taxichat_by](https://t.me/taxichat_by)
   в фоне, весь день, и складывает сообщения в локальный лог.
2. Каждое утро (по умолчанию в 07:00) собирает всё за прошедшие сутки,
   прогоняет через Claude и присылает главному короткую сводку личным
   сообщением в Telegram.

## Почему юзербот, а не обычный бот

Обычного Telegram-бота нельзя добавить в чужой публичный чат без прав
администратора — а значит через Bot API читать `t.me/taxichat_by` не
получится, если у нас там нет админки. Поэтому чтение чата идёт от имени
обычного аккаунта, который просто состоит в этом чате (через библиотеку
GramJS, вход по номеру телефона один раз, дальше по сохранённой сессии).
Отправка сводки главному, наоборот, идёт через обычного bot-а от
@BotFather — так проще и безопаснее, чем слать с личного аккаунта.

## Настройка

### 1. Установить зависимости

```bash
npm install
```

### 2. Завести API-ключи Telegram для юзербота

1. Зайти на https://my.telegram.org под аккаунтом, который состоит (или
   вступит) в чате taxichat_by.
2. API development tools -> создать приложение -> скопировать `api_id` и
   `api_hash`.
3. Скопировать `.env.example` в `.env` и вписать `TELEGRAM_API_ID` /
   `TELEGRAM_API_HASH`.

### 3. Один раз войти в аккаунт

```bash
npm run login
```

Спросит номер телефона, код из Telegram и, если включена, 2FA-пароль.
В конце выведет строку — её нужно вписать в `.env` как `TELEGRAM_SESSION`.
Дальше повторный вход не требуется.

Убедись, что этот аккаунт реально состоит в чате `t.me/taxichat_by`
(если нет — зайти в чат один раз с телефона/десктопа под этим аккаунтом).

### 4. Завести бота для отправки сводки

1. В Telegram написать [@BotFather](https://t.me/BotFather) -> `/newbot` ->
   следовать подсказкам -> скопировать токен (`123456:ABC-DEF...`).
2. Вписать его в `.env` как `DIGEST_BOT_TOKEN`.
3. Написать этому боту `/start` от имени главного (получателя сводок).
4. Открыть `https://api.telegram.org/bot<TOKEN>/getUpdates` в браузере,
   найти `"chat":{"id": ...}` и вписать это число в `.env` как
   `BOSS_CHAT_ID`.

### 5. (Рекомендуется) Ключ Anthropic для ИИ-сводки

Вписать `ANTHROPIC_API_KEY` в `.env`. Без него бот пришлёт просто сырой
список сообщений за сутки — тоже работает, но без выжимки главного.

### 6. Проверить

```bash
npm run digest:now
```

Соберёт всё, что накопилось, и сразу пришлёт сводку — так можно проверить
настройку, не дожидаясь утра.

### 7. Запустить постоянно

Локально (пока открыт терминал):

```bash
npm start
```

Чтобы бот работал всегда, даже после перезагрузки Mac — использовать
launchd (инструкция и шаблон в `deploy/com.tgstudio.taxi-morning-digest.plist.example`),
либо `pm2` (`npm i -g pm2 && pm2 start src/index.js --name taxi-digest && pm2 save`).

## Настройки расписания и часового пояса

В `.env`:

- `DIGEST_CRON` — cron-выражение времени утренней сводки (по умолчанию
  `0 7 * * *`, то есть 07:00).
- `TIMEZONE` — таймзона для расписания и для подсчёта границ "суток"
  (по умолчанию `Europe/Minsk`).

## Структура

```
src/
  config.js       читает .env
  store.js        локальное хранилище сообщений (data/messages.jsonl)
  collector.js    юзербот-клиент, тянет новые сообщения из чата
  summarize.js    сборка сводки (Claude, либо сырой список без ключа)
  sender.js       отправка сводки боссу через Bot API
  digest-job.js   логика "взять сообщения за прошедшие сутки и отправить"
  index.js        точка входа: сбор каждые 5 минут + утренняя отправка по cron
scripts/
  login.js             одноразовый вход в юзербот-аккаунт
  run-digest-now.js    ручной прогон сводки без ожидания расписания
deploy/
  com.tgstudio.taxi-morning-digest.plist.example   автозапуск на macOS
```

## Известные ограничения

- Если аккаунт юзербота выйдет из чата или потеряет доступ — сбор молча
  перестанет находить новые сообщения; стоит иногда проверять логи
  (`out.log`/`err.log` при запуске через launchd).
- История считается только с момента первого запуска `npm start` /
  `npm run digest:now` — сообщения, отправленные в чат раньше, в сводку не
  попадут (Telegram History API это позволяет добрать отдельным разовым
  скриптом при необходимости — не реализовано, т.к. не запрашивалось).
- `data/messages.jsonl` растёт бесконечно — ротацию/архивацию старых
  сообщений не делали, т.к. проект небольшой; при необходимости добавить
  отдельно.
