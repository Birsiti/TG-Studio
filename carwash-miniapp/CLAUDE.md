# carwash-miniapp — БЛЕСК

Telegram Mini App для автомойки «БЛЕСК» (Минск). Три отдельные роли —
`client.html` (клиент), `admin.html` (ресепшн/оператор), `owner.html`
(владелец) — на одном общем фундаменте. Ванильный HTML/CSS/JS без сборки,
бэкенд — Google Apps Script + Google Sheets (`Code.gs`).

**Важно: это не демо-заглушка, а гибрид.** `apiUrl` в `DEMO_CONFIG` каждого
файла указывает на реально развёрнутый Apps Script — если он отвечает,
приложение работает с настоящими данными (реальные записи, реальный
персонал, реальные цены из таблицы). Если бэкенд недоступен (сеть, скрипт
не развёрнут и т.п.) — `api()` в каждом файле тихо откатывается на
`mockApi()` с локальными моковыми данными. Из-за этого **любое изменение
моковых данных в HTML — это только фолбэк для офлайн/демо-режима, а не
правка боевых данных**. Реальные цены/персонал/записи живут в Google
Sheets и правятся через сами интерфейсы (client/admin/owner), а не через
редактирование мок-массивов в коде.

## Карта файлов

| Файл | Роль |
|---|---|
| `palettes.css` | Цветовые токены. Две независимые оси: `[data-theme]` — бренд-скин карточек (`avtohimiya`/`voda`/`chrome`/`mercedes`/`telegram`), `[data-mode]` — светлая/тёмная. Один блок = одна комбинация. |
| `theme.css` | Все компоненты (карточки, шторки, табы, кнопки и т.д.) на переменных из palettes.css. Ничего цветового не хардкодится тут напрямую. |
| `bootstrap.js` | Общий рантайм: `App` — глобальный объект. Telegram WebApp init, haptic, `confirmAsync`/`alertAsync` (обёртки над `tg.showConfirm`/`tg.showAlert`, не звать `window.confirm/alert` напрямую), резолв бренда/режима, резолв `tenant_id`, `App.loadConfig()` (реестр → фолбэк на `DEMO_CONFIG`). |
| `staff.js` | Общий модуль «Смена/Персонал» — см. отдельный раздел ниже. Используется в `admin.html` и `owner.html`. |
| `client.html` | Визард записи клиента: авто → услуги → дата/время → контакты → тикет + «Мои записи». |
| `admin.html` | Ресепшн: вкладки Сегодня / Смена / Поиск / Расписание / Услуги. |
| `owner.html` | Аналитика: вкладки Обзор / Боксы / Персонал / Склад / Магазин. |
| `Code.gs` | Единственный бэкенд-файл на одну мойку. `doPost` → `routeAction(action, payload)` → одна из ~40 функций, читающих/пишущих вкладки Google Sheets. |
| `BACKEND-README.md` | Пошаговая установка бэкенда: вкладки таблицы и их колонки, деплой Apps Script, подключение `apiUrl`, ограничения текущей версии. Читать перед любой правкой `Code.gs`. |

Ни в одном из трёх HTML-файлов нет инлайнового `<style>` — вся вёрстка
идёт через `palettes.css` + `theme.css`. Порядок подключения в `<head>`
всегда: `palettes.css` → `theme.css` → (свой `<script>` с `DEMO_CONFIG`) →
`bootstrap.js` → `staff.js` (только admin/owner) → свой `<script>` с логикой.

## Тема: два независимых переключателя

- `document.body.dataset.theme` — бренд-скин. Личный выбор пользователя
  (кнопка «палитра» в шапке), хранится в `localStorage['cw_theme_override']`
  и синхронизируется на сервер по `tg_id` через `getMyTheme`/`saveTheme`
  (лист «ТЕМЫ» — общий на все три роли, отдельный от `CONFIG.theme`).
  `CONFIG.theme` из реестра — это дефолт мойки для новых посетителей, а не
  общий переключатель для всех.
- `document.body.dataset.mode` — light/dark. Тоже личный выбор
  (`localStorage['cw_mode_override']`), по умолчанию берётся из
  `tg.colorScheme`.
- Оба резолвятся в `bootstrap.js`: `App.resolveBrand()`/`applyBrand()`,
  `App.resolveMode()`/`applyMode()`. Не путать с более простой схемой
  `data-theme=light/dark` + `data-brand=скин`, которая используется в
  других проектах студии (barbershop, toolrent-miniapp) — там имена осей
  наоборот. В carwash это `data-theme`=бренд, `data-mode`=режим.

## Мультитенантность (заложена, но не включена)

`REGISTRY_URL` в каждом файле — заглушка (`PASTE_REGISTRY_URL_HERE`).
Пока он не настроен, `App.loadConfig()` всегда возвращает
`{...DEMO_CONFIG, _demo:true}`, то есть все три файла работают как
одна конкретная мойка с захардкоженным в `DEMO_CONFIG.apiUrl` бэкендом.
Если/когда появится центральный реестр (маппинг `tenant_id` → конфиг
конкретной мойки), `?tenant=...` в URL или Telegram `start_param` начнут
реально выбирать мойку — тогда `DEMO_CONFIG.apiUrl` останется только как
офлайн-фолбэк. На сегодня это не задействовано — не путать «demo mode» в
`api()` (означает «бэкенд недоступен») с реестром (означает «мультитенантность
не настроена») — это два разных фолбэка на разных уровнях.

## Клиент (client.html)

Визард на 5 экранов (`STATE.step` 1–5): Авто → Услуги → Дата/время →
Контакты → Тикет. Полезные детали:

- **Мои машины** (`MY_CARS`/`getMyCars`) — чипы над полем номера,
  последняя использованная машина подставляется автоматически при заходе.
- **Мой профиль** (`getMyProfile`) — имя/телефон берутся из последней
  брони клиента на бэкенде (отдельного листа профилей нет).
- **Маска телефона** — свой формат `(29)123-45-67` (не студийный
  стандартный `XX-XXX-XX-XX` из skill `miniapp-style` — так исторически
  сложилось в этом проекте, при правке не «исправлять» под другой проект).
- **Прогрев** — `loadServices()`/`loadSchedule()` стартуют сразу на шаге 1,
  не дожидаясь перехода (см. `bootstrapApp()`).
- **Цены** зависят от класса авто (`legkovoy`/`krossover`/`vnedorozhnik`/
  `minivan`) — `priceFor(item)`, диапазон `[min,max]` на каждую услугу.
- Нет шага «выбор мастера/бокса» — бронь идёт на дату+время, исполнителя
  назначает админ постфактум (вкладка «Сегодня»/«Поиск» → «Кто делал»).
  Это осознанное отличие от barbershop (там клиент выбирает мастера) —
  не добавлять сюда аналог «ближайший свободный мастер», в этой модели
  выбора мастера у клиента нет вообще.

## Админ (admin.html)

Вкладки: **Сегодня** (статы + список записей на сегодня) → **Смена**
(модуль `staff.js`) → **Поиск** (по номеру/телефону, фильтр по дате) →
**Расписание** (слоты дня, рабочие часы, закрытые даты) → **Услуги**
(CRUD, поле `visible` прячет услугу от клиента, не удаляя).

Назначение исполнителя на бронь (`openBookingSheet` → «Кто делал») берёт
список из **тех, кто на смене** (`StaffModule.getShiftIds()`), не из всех
сотрудников — если чипы пустые, подсказка отправляет на вкладку «Смена».

## Владелец (owner.html)

Вкладки: **Обзор** (KPI, график за 7 дней, топ-услуги) → **Боксы**
(вручную редактируемые статусы/счётчики — пока не привязаны к бронями,
см. ограничения в BACKEND-README) → **Персонал** (модуль `staff.js`,
включая «Сегодня на смене» — раньше было только у админа) → **Склад** →
**Магазин** (автохимия на продажу клиентам, поле `visible`).

## Модуль staff.js

Единая логика «Смена + Персонал + Зарплата» для admin.html и owner.html
(до рефакторинга 2026-08-21 код дублировался в обоих файлах и был неполным
в каждом — см. «Изменения» ниже). Хост обязан:

1. Подключить `<script src="staff.js"></script>` после `bootstrap.js`.
2. Разместить в разметке контейнеры с id: `#onShiftList`, `#pickShiftBtn`,
   `#staffCount` (необяз.), `#addStaffBtn`, `#staffActiveList`,
   `#archiveSection`, `#staffArchiveList`, `#payrollFund` (необяз.).
3. Вызвать `StaffModule.init({api, haptic, showToast, openSheet, closeSheet})`
   и `StaffModule.bindButtons()` один раз при загрузке скрипта, и
   `StaffModule.renderShiftTab()` при открытии соответствующей вкладки
   (опционально с уже запущенным промисом `getStaff` первым аргументом —
   см. прогрев в owner.html `bootstrapApp()`).
4. Если хосту нужен доступ к текущему персоналу/смене вне модуля (как
   admin.html — назначение исполнителя на бронь): `StaffModule.getStaff()`,
   `StaffModule.getShiftIds()`, `StaffModule.staffById(id)`,
   `StaffModule.initials(name)`.

Архив (`active:false`) — мягкое скрытие (сотрудник пропадает из списка на
смену и назначения, но данные/история остаются). «Удалить безвозвратно» —
жёсткое `deleteStaff`, отдельная неглавная кнопка. Полный бэкенд-контракт:
`getStaff`, `saveStaff`, `deleteStaff`, `getShift`, `setShift`, `payStaff`,
`getPayouts` — все уже реализованы в `Code.gs`.

## Бэкенд (Code.gs) — на что обратить внимание при правке

- **CORS**: `fetch` намеренно шлёт `Content-Type: text/plain`, не
  `application/json` — иначе preflight, на который Apps Script не отвечает.
  Никогда не менять обратно (см. BACKEND-README «Важно про CORS»).
- **Даты/время в Sheets**: Google Sheets сам конвертирует строки вида
  `"2026-08-10"`/`"9:00"` в тип Дата/Время при записи, что потом ломает
  строковое сравнение и портит JSON. `looksLikeDateOrTime()` +
  `forcePlainText()` защищают ячейку до записи; `normalizeCell()` приводит
  обратно в строку то, что уже успело сконвертироваться раньше (старые
  строки, ручной ввод в UI таблицы). При добавлении новых полей с датами/
  временем — использовать тот же паттерн, не писать в лист напрямую мимо
  `appendRow`/`updateById`.
- **Гонки при бронировании**: `createBooking` берёт `LockService` — при
  добавлении новых мутирующих действий на общие ресурсы (слоты, остатки)
  думать, нужен ли аналогичный лок.
- **Персонал `active`**: добавлено 2026-08-21 — колонка `active` в листе
  «ПЕРСОНАЛ» (последней), `getStaffList`/`saveStaff` уже поддерживают.
  Если таблица создана до этой даты — добавить колонку `active` вручную,
  пустая ячейка трактуется как «активен».
- Полная схема вкладок и колонок — в `BACKEND-README.md`, не дублировать
  её здесь; если меняешь схему листа — обнови и README, и комментарий над
  соответствующей функцией в `Code.gs`.

## Дизайн

8px-сетка применена к отступам/радиусам во всех трёх HTML (2026-08-21).
**Исключение**: `--radius-lg/md/sm` в `palettes.css` намеренно отличаются
у бренда «premium»-типа (18/13/10 вместо стандартных 22/15/11 у остальных
скинов) — это осознанная художественная дифференциация формы под конкретный
бренд, не разнобой. Не приводить к общему знаменателю при будущих проходах
по сетке.
