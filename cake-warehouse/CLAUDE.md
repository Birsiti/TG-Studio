# cake-warehouse — ТОРТОВОЗ

Склад тортов с развозом по городам. Бренд «ТОРТОВОЗ» — рабочее название,
заменить на имя клиента (только тексты `brand-name`/`<title>`; пути файлов
не трогать — на них ведут кнопки Web App в LEADTEX).

| Файл | Роль | Статус |
|---|---|---|
| `sklad.html` | Кладовщик: Остатки (пересчёт, списание) / Приход / Рейсы (сборка → отгрузка → приёмка) / Тара / Журнал (+CSV) | **рабочий** |
| `driver.html` | Водитель: мои рейсы, отчёт о возврате тортов и тары | демо |
| `admin.html` | Склад: Сводка / Смены / Справочники (торты, города, люди, тара) | демо |
| `brand.css` | Шоколад + сливки, малиновый акцент, мятный «холод»; Montserrat Alternates / Nunito Sans / Space Mono; код города `.code`, накладная `.waybill`, термо-плашка `.thermo` | |
| `mock.js` | `CakeMock` — двойник контракта в localStorage | |

Бэкенд — `api/bots/cake.py` (`/api/cake`), тесты — `api/tests/test_cake.py`.

## Учёт

- Остаток = сумма журнала `moves` (qty со знаком). Ничего не редактируется
  задним числом: ошибку исправляют пересчётом (`adjustStock` пишет разницу).
- Рейс: `draft` (сборка, остаток не трогает) → `shipTrip` списывает
  торты и вешает тару долгом на город → `shipped` → водитель `reportTrip`
  → `reported` → кладовщик `closeTrip`: годные возвраты обратно на
  остаток, брак только фиксируется в рейсе, тара снимается с долга.
- Тара: долг города = сумма `tara_moves`; на складе = «всего в обороте» − долг.
- Нет ежедневного «освежения» демо и нет обрезки старых строк — это учёт.

## Доступ

`TGS_CAKE_ADMINS=<tg id>,<tg id>` в окружении API включает рабочий режим:
пускаются только эти id и активные сотрудники с заполненным Telegram id
(справочник «Люди»). Водитель с привязанным id видит только свои рейсы.
Без переменной — открытое демо.

`TGS_CAKE_BOT_TOKEN=<токен из @BotFather>` включает проверку подписи
Telegram (`verify_init_data` в `api/core.py`, срок 24 ч): запрос без
подписи этого бота отклоняется (`forbidden`), а пользователь берётся из
подписи, не из `userId`. Токен — только в окружении API на iMac, в
репозиторий не коммитить. Боевой режим = обе переменные.

## Данные

- **Ассортимент — реальный**: 94 позиции из заявок клиента (фото накладных
  от 17.10.2026, `source/`), `CATALOG` в `api/bots/cake.py`, 5 категорий: Торт, Венский
  десерт, Пирожное, Набор пирожных, Сладости мучные. Одно название бывает
  в разных весах (Сникерс 0,4 / 0,8 кг) — везде показываем «название, вес».
  `mock.js` содержит тот же список, сгенерированный из Python: правка
  только в `cake.py`, потом перегенерировать.
- Тара — «Ящик» и «Стопка» (как в листе сборки); количество в обороте —
  заглушка, уточнить у клиента.
- Города, сотрудники и остатки — пока демо. Перед запуском удалить
  `data/cake.db*`, чтобы база создалась заново.
