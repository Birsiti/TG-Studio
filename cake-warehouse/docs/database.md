# База данных

Две схемы, обе SQLite на iMac:

| | Где | Модель | Статус |
|---|---|---|---|
| База приложения | `api/bots/cake/schema.py` → `TGS_DATA_DIR/cake.db` | Рейс в город | Работает сейчас |
| База под реальный процесс | `cake-warehouse/db/schema/*.sql` | Маршрут → заказчик → точка → заявка → сводная | Готова, приложение переводится на неё |

## База приложения (`schema.py`)

| Таблица | Что |
|---|---|
| `products` | Ассортимент: категория, название, вес единицы, срок, минимальный остаток |
| `cities`, `staff`, `tara_types` | Города, люди (роль, телефон, машина, Telegram id), виды тары |
| `moves` | **Журнал тортов**: `type` in/ship/return/writeoff/adjust, `qty` со знаком. Остаток = сумма |
| `trips` | Рейсы: строки, ящики, отчёт водителя (JSON), даты этапов |
| `tara_moves` | **Журнал ящиков**: `driver_id`, `kind` out/back/writeoff, `qty` со знаком. Долг = сумма |
| `shifts` | Кто на смене в день |
| `points` | Точки разгрузки: заказчик, адрес, маршрут, № магазина |
| `orders` | Заявки точек на дату: строки и галочки сборки (JSON), `new` → `picked`, кто собрал, ящики |
| `places` | Место торта на складе — № по кругу против часовой от двери |

Таблицы сборки добавляются в уже работающую базу сами: схема создаёт их
при старте API, `migrate` (`orders_seed.py`) один раз вносит точки и
заявки с фото (`meta.orders_v1`).

Строки демо-данных помечены `seed=1`. Старые строки не удаляются.

## База под реальный процесс (`db/schema/`)

Файлы применяются по порядку номеров:

| Файл | Что |
|---|---|
| `01_refs.sql` | Категории, товары (+ **место на складе**), маршруты, заказчики, точки разгрузки, люди, тара, смены |
| `02_route_sheets.sql` | Сводная маршрута на дату = лист сборки: сборщик, ящики, стопки, водитель, статусы |
| `03_orders.sql` | Заявки клиента (номер, точка, маршрут, комментарий), строки (кол-во, места, бонус), возвраты |
| `04_journals.sql` | `stock_moves` (торты), `tara_moves` (ящики за водителем) |
| `05_triggers.sql` | Ящики только водителю и не ниже нуля; журнал не правится и не удаляется; заявка — только в сводную своего маршрута и даты |
| `06_views_stock.sql` | `v_stock`, `v_order_totals` (как «Итого» накладной), `v_route_summary`, `v_route_shortage` |
| `07_views_tara.sql` | `v_driver_tara` (выдано/вернул/утерял/долг), `v_sheet_tara`, `v_tara_stock` |
| `08_views_pick.sql` | `v_pick_order`, `v_pick_route` — листы сборки по кругу |

Данные — `seed.sql`, генерируется `build_seed.py`: 94 товара,
2 маршрута, 8 заказчиков, 24 точки, 11 заявок с фото (каждая сверена с
«Итого» накладной).

### Команды

```bash
python3 cake-warehouse/db/build_seed.py          # пересобрать seed.sql
python3 cake-warehouse/db/check_db.py            # собрать во временный файл и проверить
python3 cake-warehouse/db/check_db.py cake.db    # создать файл базы
cat cake-warehouse/db/schema/*.sql | sqlite3 cake.db && sqlite3 cake.db < cake-warehouse/db/seed.sql
sqlite3 -header -column cake.db < cake-warehouse/db/queries.sql   # частые отчёты
```

Посмотреть глазами — DB Browser for SQLite.
Подробнее о данных с фото и проверках — `cake-warehouse/db/README.md`.

## Правила

- Остаток и долг по ящикам не хранятся полем — только сумма журнала.
- Ошибку исправляют новой записью (`adjust`, возврат), а не правкой старой.
- Одно название бывает в разных весах — товар = категория + название + вес.
